# Аппаратное ускорение (SIMD & Vectorization)

В основе аналитической мощи `RawDB` лежит колоночная архитектура, которая идеально подходит для векторизованного выполнения (Vectorized Execution). Начиная с версии 0.1, `RawDB` использует инструкции **AVX-512** и **AVX2** (Advanced Vector Extensions) для аппаратного ускорения фильтрации и обработки данных.

## Почему SIMD?

Традиционные транзакционные (Row-based) СУБД вроде PostgreSQL или SQLite обрабатывают данные построчно (Tuple-at-a-time). При выполнении запроса `SELECT * FROM users WHERE age > 18` база данных:
1. Извлекает одну строку (попутно подтягивая ненужные для условия байты в кэш процессора).
2. Вызывает функцию сравнения.
3. Переходит к следующей строке.
Это вызывает огромное количество промахов в кэше (cache misses) и не позволяет процессору использовать свой конвейер на 100%.

Колоночная архитектура `RawDB` хранит колонки как единый непрерывный массив (в виде DataChunks). Это позволяет нам применить подход Single Instruction, Multiple Data (SIMD). 

С помощью 512-битных регистров AVX-512 (или 256-битных AVX2) мы загружаем **сразу 16 или 8 чисел** из памяти в процессор и сравниваем их с условием за **один такт CPU**.

## Архитектура реализации

Весь код, специфичный для архитектуры процессора (интринсики `_mm512_*` и `_mm256_*`), полностью изолирован в заголовочном файле `src/query/simd_ops.hpp`. Бизнес-логика движка остается чистой и ничего не знает об аппаратных деталях.

### Поддерживаемые типы данных
Векторизация в данный момент активно используется для примитивов фиксированной ширины:
- **`INT32`** — обрабатывается по 16 (AVX-512) или 8 (AVX2) элементов за такт.
- **`INT64` / `TIMESTAMP`** — обрабатывается по 8 или 4 элемента за такт.
- **`FLOAT64`** — обрабатывается по 8 или 4 элемента за такт.

Строки (`VARCHAR`) пока обрабатываются скалярно из-за переменной длины и специфики сравнения символов.

### Кроссплатформенность и Fallback
`RawDB` — это встраиваемая и портативная СУБД. Мы не заставляем пользователей использовать только современные x86 процессоры. В движке реализована динамическая диспетчеризация (Dynamic Dispatch).

В `simd_ops.hpp` встроена поддержка условной компиляции:
```cpp
#if defined(__AVX512F__)
    // Максимальная скорость с 512-битными регистрами
#elif defined(__AVX2__)
    // Высокоскоростной код с _mm256_*
#else
    // Стандартный C++ fallback для ARM (Apple Silicon) или старых процессоров
#endif
```
Система сборки CMake автоматически определяет, можно ли использовать флаги `-mavx512f` и `-mavx2`. Если их использование отключено, база данных бесшовно откатится на скалярное выполнение.

## Показатели производительности (Benchmarks)

Векторизация переворачивает традиционные представления о производительности SQL. Благодаря Arena Allocator и SIMD-фильтрам, `RawDB` достигает впечатляющей пропускной способности (Memory Bandwidth).

Пример бенчмарка на 10,000,000 строк (полностью исключает кэш процессора):
- `SELECT * FROM table`: **~277.6 млн. строк/сек**
- `SELECT * FROM table WHERE id > 50000`: **~183.8 млн. строк/сек**

SIMD-фильтр за микросекунды отбрасывает лишние данные на самом нижнем уровне хранения. В результате дорогостоящие проверки MVCC-видимости и форматирование вывода применяются только к нужным строкам.
