# Аппаратное ускорение (SIMD & Vectorization)

В основе аналитической мощи `rawDB` лежит колоночная архитектура, которая идеально подходит для векторизованного выполнения (Vectorized Execution). Начиная с версии 0.1, `rawDB` использует инструкции **AVX2** (Advanced Vector Extensions 2) для аппаратного ускорения фильтрации и обработки данных.

## Почему SIMD?

Традиционные транзакционные (Row-based) СУБД вроде PostgreSQL или SQLite обрабатывают данные построчно (Tuple-at-a-time). При выполнении запроса `SELECT * FROM users WHERE age > 18` база данных:
1. Извлекает одну строку (попутно подтягивая ненужные для условия байты в кэш процессора).
2. Вызывает функцию сравнения.
3. Переходит к следующей строке.
Это вызывает огромное количество промахов в кэше (cache misses) и не позволяет процессору использовать свой конвейер на 100%.

Колоночная архитектура `rawDB` хранит колонку `age` как единый непрерывный массив `std::vector<int32_t>`. Это позволяет нам применить подход Single Instruction, Multiple Data (SIMD). 

С помощью 256-битных регистров AVX2 мы загружаем **сразу 8 чисел** из памяти в процессор и сравниваем их с числом `18` за **один такт CPU**.

## Архитектура реализации

Весь код, специфичный для архитектуры процессора (интринсики `_mm256_*`), полностью изолирован в заголовочном файле `src/query/simd_ops.hpp`. Бизнес-логика движка остается чистой и ничего не знает об аппаратных деталях.

### Поддерживаемые типы данных
Векторизация в данный момент активно используется для примитивов фиксированной ширины:
- **`INT32`** — обрабатывается по 8 элементов за такт.
- **`INT64`** — обрабатывается по 4 элемента за такт.
- **`FLOAT64`** — обрабатывается по 4 элемента за такт.

Строки (`VARCHAR`) пока обрабатываются скалярно из-за переменной длины и специфики сравнения символов.

### Кроссплатформенность и Fallback
`rawDB` — это встраиваемая и портативная СУБД. Мы не заставляем пользователей использовать только современные x86 процессоры. 

В `simd_ops.hpp` встроена условная компиляция:
```cpp
#if defined(__AVX2__)
    // Высокоскоростной код с _mm256_loadu_si256 и _mm256_cmpgt_epi32
#else
    // Стандартный C++ fallback для ARM (Apple Silicon) или старых x86 процессоров
#endif
```
Система сборки CMake автоматически определяет, можно ли использовать флаг `-mavx2`. Если его использование отключено (переменная `RAWDB_ENABLE_AVX2=OFF` или целевая архитектура не x86_64), база данных бесшовно откатится на скалярное выполнение.

## Показатели производительности (Benchmarks)

Векторизация переворачивает традиционные представления о производительности SQL. Зачастую, сканирование с фильтром (`WHERE`) выполняется **быстрее**, чем простое сканирование (`SELECT *`).

Пример бенчмарка на 100,000 строк:
- `SELECT * FROM table`: **~9.4 млн. строк/сек**
- `SELECT * FROM table WHERE id > 50000`: **~16.5 млн. строк/сек**

Такая "аномалия" возникает потому, что SIMD-фильтр за микросекунды отбрасывает 50% данных на самом нижнем уровне хранения. В результате дорогостоящие проверки MVCC-видимости (чтение хеш-таблиц индексов транзакций) и форматирование вывода применяются только к оставшейся половине строк.
